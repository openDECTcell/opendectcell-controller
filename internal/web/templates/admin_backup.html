What to back up

A controller has two things that cannot be rebuilt, and they must be kept apart:

The databaseUsers, handsets and their (encrypted) keys, cells, settings, call log, audit log. Dump it regularly.
The master keyWithout it the database's secrets (handset keys, SIP passwords, two-factor secrets, the cell CA) cannot be read, and with it next to the dump anyone holding the dump can. Store it separately, offline.

The cells' own certificates are in the database, so a restored controller is recognised by its cells without enrolling them again.

With Docker Compose

docker compose exec db pg_dump -U opendectcell -Fc opendectcell > opendectcell-$(date +%F).dump
docker compose cp controller:/secrets/master_key ./master_key.backup

To restore: start an empty stack, stop the controller, load the dump (pg_restore --clean --if-exists -d opendectcell), put the same master key back, start the controller. docs/deployment.md has the full procedure and how to rotate the key.

This page only explains: the controller does not make backups itself, because the dump belongs next to your other backups, not inside the application.

Check a backup by restoring it into a scratch instance now and then.
